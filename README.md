# Recovery of a 10x Genomics 3' Gene Expression run and Cell Ranger processing

This repository documents the workflow used to recover a NextSeq 2000 / 10x Genomics 3' Gene Expression run with severe demultiplexing failure, requeue BCL Convert with a modified Index 1 strategy, download the recovered FASTQs from BaseSpace Sequence Hub, and prepare/run Cell Ranger.

## 1. Dataset and sequencing configuration

Platform:

- Illumina NextSeq 2000
- 10x Genomics Chromium Universal 3' Gene Expression
- Dual Index Kit TT Set A
- Four libraries
- Read configuration: R1 28 bp / I1 10 bp / I2 10 bp / R2 90 bp
- BCL Convert version used by BaseSpace: 4.5.4

Samples and physical index positions:

| Sample | TT Set A well | i7 / Index 1 | i5 / Index 2 entered in Sample Sheet |
|---|---|---|---|
| P11 | A01 | GTAACATGCG | AGTGTTACCT |
| DMem | A02 | GTGGATCAAA | GCCAACCCTG |
| P11_O | A03 | CACTACGAAA | TTAGACTGAT |
| O | A04 | CTCTAGCGAG | TATCTTCATC |

The sample/index assignments were checked against the 10x TT Set A information before reprocessing.

## 2. Original demultiplexing problem

The original BCL Convert output contained 1,429,126,941 reads in total, but 1,363,114,160 reads were classified as Undetermined.

| Sample | Original assigned reads | Original % of run |
|---|---:|---:|
| P11 | 5,661,105 | 0.40% |
| DMem | 16,888,206 | 1.18% |
| P11_O | 16,851,455 | 1.18% |
| O | 26,612,015 | 1.86% |
| Undetermined | 1,363,114,160 | 95.38% |

Inspection of `Top_Unknown_Barcodes.csv` showed that the expected i7 sequences were present but with strong no-call/mismatch patterns concentrated at the end of Index 1. Representative high-count unknown barcodes included:

```text
Expected i7   Observed dominant pattern
CTCTAGCGAG -> CTCTAGCNAN
CACTACGAAA -> CACTACGNAN
GTGGATCAAA -> GTGGATCNAN
GTAACATGCG -> GTAACATNCN
```

The original configuration was:

```text
OverrideCycles,U28;I10;I10;Y90
```

The rescue configuration was:

```text
OverrideCycles,U28;I7N3;I10;Y90
```

Interpretation:

- `U28`: keep all 28 cycles of Read 1 as UMI/cell-barcode read according to the 10x library configuration
- `I7`: use the first seven cycles of Index 1 for demultiplexing
- `N3`: ignore the final three cycles of Index 1
- `I10`: use all ten cycles of Index 2
- `Y90`: use all 90 cycles of Read 2

Because only seven cycles of Index 1 are marked as `I`, the i7 sequences supplied to `[BCLConvert_Data]` were shortened to their first seven bases.

## 3. Rescue Sample Sheet changes

The physical sequencing cycles in `[Reads]` were **not changed**:

```text
[Reads]
Read1Cycles,28
Read2Cycles,90
Index1Cycles,10
Index2Cycles,10
```

The library preparation metadata was also kept:

```text
[Sequencing_Settings]
LibraryPrepKits,10x3PrimeUniversalGeneExpression
```

The BCL Convert settings were changed only for Index 1 masking:

```text
[BCLConvert_Settings]
SoftwareVersion,4.5.4
NoLaneSplitting,true
TrimUMI,0
OverrideCycles,U28;I7N3;I10;Y90
FastqCompressionFormat,gzip
```

The effective demultiplexing indices became:

```text
[BCLConvert_Data]
Sample_ID,Index,Index2
P11,GTAACAT,AGTGTTACCT
DMem,GTGGATC,GCCAACCCTG
P11_O,CACTACG,TTAGACTGAT
O,CTCTAGC,TATCTTCATC
```

For the requeued cloud output, a separate project name was used:

```text
Wanessa_P11-4_rescue_I1_7bp
```

The archival record of the final rescue Sample Sheet configuration is in:

```text
configs/SampleSheet_rescue_I1_7bp_record.csv
```

**Important:** the `[Cloud_Settings]` fields are generated by BaseSpace and are run/account specific. Do not copy those values to an unrelated sequencing run. For another run, start from that run's original Sample Sheet and reproduce only the documented BCL Convert changes.

## 4. Demultiplexing rescue result

The requeue recovered the large majority of previously Undetermined reads.

| Sample | Original reads | Rescue reads |
|---|---:|---:|
| P11 | 5,661,105 | 232,025,531 |
| DMem | 16,888,206 | 309,803,906 |
| P11_O | 16,851,455 | 313,022,691 |
| O | 26,612,015 | 490,138,085 |
| Undetermined | 1,363,114,160 | 84,136,728 |

Total reads remained exactly:

```text
1,429,126,941
```

Assigned reads increased from:

```text
66,012,781
```

to:

```text
1,344,990,213
```

This corresponds to approximately 94.11% of all reads being assigned after rescue, compared with only 4.62% before rescue.

Residual one-mismatch fractions in the recovered data were:

| Sample | Perfect match | One mismatch |
|---|---:|---:|
| P11 | 41.26% | 58.74% |
| DMem | 23.63% | 76.37% |
| P11_O | 98.09% | 1.91% |
| O | 98.16% | 1.84% |

These metrics are retained as QC information and should be considered when interpreting the downstream Cell Ranger results.

## 6. BaseSpace CLI installation on Windows

The official Illumina BaseSpace CLI binary for Windows can be installed directly from the Illumina launcher.

Run PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process Bypass

.\scripts\00_install_basespace_cli.ps1
```

The script:

1. creates a dedicated CLI directory
2. downloads the current Windows `bs.exe`
3. adds that directory to the current session PATH
4. optionally adds it to the user PATH
5. runs `bs auth`
6. verifies the authenticated account

Illumina documentation:
https://developer.basespace.illumina.com/docs/content/documentation/cli/cli-overview

## 7. BaseSpace CLI authentication

Authentication is interactive:

```powershell
bs.exe auth
```

A browser window is opened to authorize the CLI against the BaseSpace Sequence Hub account/workgroup. After authentication:

```powershell
bs.exe whoami
bs.exe list projects
```

If the required project is in a specific workgroup, authentication must be performed while that workgroup is active.

## 8. Backing up the original data before requeue

The rescued project was downloaded with:

```powershell
bs.exe download project `
  -i  <ORIGINAL_BASESPACE_PROJECT_ID>`
  -o "...\02_rescue_I1_7bp" `

```

The expected recovered FASTQs are:


## 10. Cell Ranger version

At the time this workflow was finalized, the current Cell Ranger release was:

```text
Cell Ranger 10.1.0
```

The updated installation is kept alongside the old one rather than deleting it.

The 10x software package must be obtained from the official 10x Genomics download page after accepting the license. The direct tarball URL is session/license dependent, so it is deliberately not hard-coded in this repository.

Official installation documentation:
https://www.10xgenomics.com/support/software/cell-ranger/latest/tutorials/cr-tutorial-in

Run:

```bash
bash scripts/03_install_cellranger_10.1.sh \
  /path/to/cellranger-10.1.0.tar.xz
```

The script installs it under:

```text
/mnt/e/WSL/Linux-Ubuntu/cellranger-10.1.0
```

and adds it to `PATH` without deleting Cell Ranger 10.0.0.

## 12. Validate FASTQs before Cell Ranger

From WSL:

```bash
bash scripts/04_validate_fastqs.sh \
  /mnt/e/BaseSpace/Wanessa/02_rescue_I1_7bp
```

The script checks:

- that all 8 expected FASTQs exist
- that R1/R2 pairs exist for all 4 samples
- file sizes
- gzip integrity
- that no `Undetermined` file will be used as a Cell Ranger input

Because `gzip -t` reads the complete compressed files, this integrity check can take a long time on ~100 GB datasets.

## 13. Cell Ranger working directory

Create a dedicated output directory:

```bash
mkdir -p /mnt/e/BaseSpace/Wanessa/CellRanger_Wanessa
cd /mnt/e/BaseSpace/Wanessa/CellRanger_Wanessa
```

Before running:

```bash
cellranger --version
nproc
free -h
df -h /mnt/e
```

10x currently lists 8 cores / 64 GB RAM as minimum system requirements for Cell Ranger, with substantially more recommended for larger datasets.

## 14. Cell Ranger count

The script runs samples sequentially to avoid competing for RAM and disk I/O:

```bash
bash scripts/05_run_cellranger_count.sh
```

Core configuration:

```bash
REF=/mnt/e/WSL/Linux-Ubuntu/refdata-gex-GRCh38-2024-A
FASTQ_ROOT=/mnt/e/BaseSpace/Wanessa/02_rescue_I1_7bp
OUT_ROOT=/mnt/e/BaseSpace/Wanessa/CellRanger_Wanessa
```

The four analyses are:

```text
P11
DMem
P11_O
O
```

No chemistry is forced. Cell Ranger chemistry autodetection is allowed to determine the appropriate 10x chemistry from the reads.

No `--expect-cells` is supplied. Current Cell Ranger versions can estimate the recovered cell count automatically.

The default workflow in this repository uses:

```text
--create-bam=false
```

If a BAM is needed, change `CREATE_BAM=false` to `CREATE_BAM=true` before running.

Example for P11:

```bash
cellranger count \
  --id=P11 \
  --transcriptome=/mnt/e/WSL/Linux-Ubuntu/refdata-gex-GRCh38-2024-A \
  --fastqs=/mnt/e/BaseSpace/Wanessa/02_rescue_I1_7bp/P11_ds \
  --sample=P11 \
  --create-bam=false
```

The actual script automatically discovers the dataset subdirectory containing each sample FASTQ, so BaseSpace's generated dataset suffix does not need to be hard-coded.

10x documentation:
https://www.10xgenomics.com/support/software/cell-ranger/latest/analysis/running-pipelines/cr-gex-count

## 17. GitHub safety

Do **not** push FASTQs, BAMs, Cell Ranger output matrices containing restricted data, BaseSpace authentication files/tokens, or 10x software tarballs to GitHub.

The `.gitignore` in this repository excludes the major large/sensitive file types.
